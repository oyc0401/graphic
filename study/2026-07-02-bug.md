지금 리사이즈+히스토리조작할 때 버그가 너무 심한데 playwright로 버그원인 잡고 고쳐줘



한 줄짜리 JavaScript 스코프 버그였습니다. resize.ts의 undo 함수 안에서 이렇게 돼 있었어요:

undo: async () => {
  sourceTextureManager.setSize();   // ← 여기서 쓰는데
  ...
  const sourceTextureManager = getSourceTextureManager(...);  // ← 밑에서 또 선언
  ...
}

문제: JS에서 const로 변수를 선언하면 그 변수는 함수 블록 맨 위로 끌어올려집니다(호이스팅). 근데 const는 실제 선언줄에 도달하기 전까지는 "아직 못 쓰는 상태(TDZ, Temporal Dead Zone)"예요.

그래서:
- 원래는 위쪽 sourceTextureManager.setSize()가 바깥에 이미 만들어둔 매니저를 쓰려던 거였는데,
- 밑에 const sourceTextureManager = ...를 또 선언하는 순간, 함수 전체에서 그 이름이 지역 변수로 덮어써짐(섀도잉).
- 결과적으로 위쪽 줄이 "아직 초기화 안 된 지역 변수"를 건드리게 돼서 Cannot access 'sourceTextureManager2' before initialization 에러가 터지고, undo가 통째로 멈춰버린 거예요.

redo는 똑같은 구조인데 이 재선언이 없어서 멀쩡했고 → undo만 깨지고 redo는 됨이 딱 맞아떨어졌죠.

고친 방법: 밑에 중복 선언한 그 한 줄만 지웠습니다. 바깥에 이미 있는 걸 그대로 쓰면 되니까요 (같은 캐시 인스턴스라 동작도 동일).

즉 "리사이즈+히스토리" 로직 자체가 잘못된 게 아니라, undo 함수 안에 변수를 실수로 두 번 선언해서 생긴 순수 문법 스코프 버그였습니다.
