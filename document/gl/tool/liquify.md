(WebGL 기본 설명은 생략하고 코드의 논리적 흐름과 구조만을 자세히 다룹니다.)

## 🗺️ LiquifyManager의 핵심 개념과 동작 원리

Liquify 기능은 사용자가 이미지를 마우스로 밀거나 당겨서 **이미지 픽셀을 유동적으로 변형**시키는 기능입니다.

이 기능은 다음과 같은 핵심 원리로 작동합니다.

- **"변위맵(displacement map)"**이라는 특수 텍스처를 사용하여, 이미지 픽셀의 이동 정도와 방향을 저장합니다.
- 사용자의 입력을 받아서 **변위맵을 업데이트**하고, 업데이트된 변위맵을 기반으로 이미지를 렌더링합니다.
- 히스토리를 관리할 때는 바로 이 **변위맵 데이터를 저장 및 복구**하면 됩니다.

---

## 🎯 LiquifyManager 내부 데이터 흐름

LiquifyManager는 다음 두 단계로 동작합니다.

### 1️⃣ **Push 단계**
- 사용자가 이미지를 밀면(push) → **변위맵**을 업데이트합니다.
- 사용자가 입력한 시작점과 끝점의 움직임을 계산하여 **픽셀 이동 방향과 강도**를 변위맵(`displacementTex`)에 저장합니다.
- 이 때, Ease Integral(부드러운 밀기 효과) 텍스처를 사용하여 자연스럽게 보간 처리됩니다.

### 2️⃣ **Render 단계**
- 최종적으로 변위맵을 사용하여 이미지를 실제로 변형된 형태로 화면에 렌더링합니다.
- 렌더링 시, 변위맵을 통해 원본 이미지 픽셀을 변형된 위치로 이동하여 보여줍니다.

즉, 전체 흐름은 다음과 같습니다.

```
[사용자 입력] → 변위맵 업데이트 → 렌더링 시 변위맵 참조 → 이미지 변형
```

---

## 📌 주요 텍스처 4가지 이해하기 (중요🔥)

- **displacementTex**: 현재의 변위맵 (밀고 당긴 결과)
- **displacementTexOut**: 변위맵 업데이트 중간 결과 저장용 텍스처
- **sourceDisplacementTex**: 히스토리 및 취소(`cancel`) 기능을 위한 원본 변위맵 백업
- **원본 이미지 텍스처(`u_sourse`)**: 실제 원본 이미지 데이터 (레이어에서 가져옴)

---

## 📐 두 개의 주요 셰이더 설명

### 🔹 **Liquify Push Shader (`liquifyPushShader`)** 🔹
- **목적**: 사용자의 마우스 움직임에 따라 변위맵을 계산/업데이트
- 입력: 시작점(`u_start`), 끝점(`u_end`), 브러시 크기(`u_radius`), 강도(`u_strength`)
- 출력: 각 픽셀의 이동 방향 및 거리 계산 후 변위맵에 저장

### 🔹 **Render Shader (`renderShader`)** 🔹
- **목적**: 변위맵을 이용해 이미지를 실제로 변형하여 렌더링
- 입력: 변위맵(`u_displacement`), 원본 이미지(`u_sourse`)
- 출력: 최종적으로 화면에 나타나는 변형된 이미지 픽셀들

## 🧩 LiquifyManager 객체의 주요 메서드 설명

| 함수명 | 설명 |
|--------|------|
| `enter()` | Liquify 모드 진입 (초기화) |
| `start(pointer)` | 사용자가 입력 시작 시 초기 범위 설정 |
| `push(start, end)` | 변위맵을 업데이트 |
| `render()` | 변위맵을 기반으로 이미지 실제 렌더링 |
| `end()` | 입력 끝 (변위맵을 히스토리 저장용 백업에 복사) |
| `cancel()` | 취소 시 변위맵을 이전 상태로 복원하고 렌더링 |
| `exit()` | 모드 종료 (변위맵 초기화 및 원본 저장) |
| `setSize()` | 캔버스 크기 변경 시 텍스처 재조정 |
| `setStrength(s)` | 밀고 당기기의 강도 조절 |

## ♻️ 히스토리와 취소(`cancel`) 기능을 위한 핵심 로직 이해하기 (매우 중요🔥)

Liquify 기능의 히스토리 및 취소 기능은 변위맵의 복사(`transfer`)로 구현됩니다.

### **변위맵 히스토리의 핵심**

- Liquify 적용이 끝날 때(`end()`), 현재의 변위맵(`displacementTex`)을  
  `sourceDisplacementTex`(히스토리용 백업 텍스처)에 복사하여 저장합니다.
- 취소(`cancel`) 시, 저장된 히스토리용 텍스처(`sourceDisplacementTex`)를 다시 현재 변위맵으로 복원하여 이전 상태로 돌립니다.

즉, 히스토리 기능은 **변위맵 자체를 저장하고 복원**하는 것으로 간단히 구현 가능합니다.

---

## 🚧 `transfer(aTex, bTex)` 함수의 역할과 사용법

```js
transfer(aTex, bTex);
```

이 함수는 두 텍스처 사이의 데이터를 복사(blit)하는 역할을 합니다.

- `transfer(displacementTex, sourceDisplacementTex)`  
  → 현재 변위맵을 히스토리용으로 복사 (입력 완료 후 히스토리 저장용)
- `transfer(sourceDisplacementTex, displacementTex)`  
  → 히스토리에서 이전 상태를 복구 (취소 기능 수행 시 사용)

이 함수가 히스토리 구현의 핵심입니다.

---

## ✅ 히스토리 기능 개발 시 고려해야 할 내용 (필수 체크리스트)

히스토리 기능은 아래 내용만 구현하면 됩니다.

- 매 Liquify 입력이 끝날 때(`end()`), 변위맵을 히스토리에 저장 (복사)
- 취소(`cancel`) 시, 히스토리에서 변위맵을 복구하여 상태를 되돌림
- 히스토리 스택을 배열로 관리하고, undo/redo 로직을 구현

변위맵 저장은 위에서 소개한 `transfer()` 함수를 그대로 사용하면 쉽게 구현 가능합니다.

## 🚨 히스토리에 꼭 저장해야 하는 정보

Liquify 모드의 히스토리에는 다음 정보를 반드시 저장해야 합니다.

- 변위맵 데이터 (`sourceDisplacementTex`의 텍스처 데이터를 복사하여 저장)
- 필요시 변경 영역 정보(`pathDirtyRect`)도 함께 저장하면 더 효율적임 (선택적)

이 정보만 있으면 Liquify의 모든 상태를 정확히 저장하고 복구할 수 있습니다.

## 🎯 LiquifyManager 구조 요약 및 히스토리 연결 흐름

```
사용자 입력 (push) → 변위맵 업데이트 (displacementTex) → render로 실제 이미지 변형

입력 끝(end) → displacementTex → 히스토리(sourceDisplacementTex에 저장)

취소(cancel) → 히스토리(sourceDisplacementTex) → displacementTex 복구 → render 재호출
```
