# 🖌️ 브러시 매니저 구조 완벽 가이드 (for 히스토리 기능 개발자)

이 문서는 **브러시 관리 로직**을 히스토리 기능 개발자가 95% 이상 이해할 수 있도록 **매우 자세히 설명**한 문서입니다.  
(WebGL 자체 설명은 생략하며, 코드 흐름과 목적을 중점적으로 다룹니다.)

---

## 🚩 전체 구조 개요

브러시 로직은 크게 **4개의 셰이더 프로그램**과 **브러시 매니저 객체**로 구성됩니다.

- `strokeShader` → 브러시의 모양을 알파맵에 그리는 셰이더 (**핵심**)
- `brushShader` → 실제 이미지에 브러시 색상을 입히는 셰이더
- `eraserShader` → 지우개 기능을 구현하는 셰이더
- 브러시 매니저 (`brushManager`) → 모든 브러시 작업을 관리하는 객체 (싱글톤)

---

## 🚩 핵심 데이터 흐름

브러시 동작은 **두 단계**로 나눠서 실행됩니다.

1. **stroke 단계**: 
   - 사용자가 그리는 선분을 기반으로 "브러시의 알파맵"을 생성.
   - 사용자의 입력(start, end 좌표)을 바탕으로 매 프레임마다 선분을 알파맵(`pathTex`)에 그립니다.
   - 이때 **16샘플 SSAA** 방식으로 경계를 매우 부드럽게 처리합니다.

2. **brush 또는 eraser 단계**:
   - 위 알파맵을 기반으로 실제 이미지(레이어)에 색을 입히거나 지웁니다.
   - `brushShader`는 알파맵을 사용해 브러시 색상을 적용하고,  
     `eraserShader`는 알파맵을 사용해 투명도를 적용하여 지웁니다.

즉, **브러시 입력 → strokeShader 알파맵 생성 → brushShader 또는 eraserShader로 이미지 변경**의 구조입니다.

---

## 🚩 WebGL의 핵심 텍스처들 이해

### 주요 텍스처는 총 3개입니다.

- `pathTex`: 알파맵 텍스처 (브러시의 형태를 담고 있음, float 텍스처)
- `pathTexOut`: 중간 렌더링 결과를 담는 텍스처 (알파맵 업데이트 시 사용)
- 원본 이미지 텍스처 (`u_sourse`): 레이어에 저장된 실제 그림 데이터

---

## 🚩 각 셰이더 역할 명확히 이해하기

### 1️⃣ **strokeShader**: (가장 중요한 셰이더)

- **입력**: start, end 좌표 (`u_start`, `u_end`), 브러시 크기 (`u_radius`), 불투명도 (`u_alpha`)
- **출력**: 픽셀마다 브러시의 커버리지를 계산해 알파값으로 출력
- 내부에서는 선분과 픽셀 거리를 계산해서, 부드럽고 정확한 브러시 테두리를 만듦 (16샘플 수동 SSAA 적용)

### 2️⃣ **brushShader**:

- **입력**: 알파맵(`u_pathMap`), 원본 이미지 텍스처(`u_sourse`), 브러시 색상(`u_color`)
- **출력**: 실제 이미지 위에 브러시 색상을 알파맵을 이용해 블렌딩 (Premultiplied Alpha 사용)

### 3️⃣ **eraserShader**:

- **입력**: 알파맵(`u_pathMap`), 원본 이미지 텍스처(`u_sourse`)
- **출력**: 기존 이미지를 알파맵으로 가려서 지우개 효과 구현 (투명도 감소)

---

## 🚩 브러시 매니저의 함수 이해하기

브러시 매니저 객체(`brushManager`)는 다음과 같은 메서드를 제공합니다.

| 함수명 | 역할 |
|--------|------|
| `enter()` | 브러시 모드 진입 (UI 표시 등 초기화) |
| `start(p)` | 브러시 입력 시작 (첫 터치 좌표) |
| `stroke(start, end)` | 터치 이동 시 매 프레임 호출 (알파맵 업데이트) |
| `brush()` | 알파맵을 이용해 실제 브러시로 색상 적용 |
| `eraser()` | 알파맵을 이용해 실제 이미지를 지움 |
| `end()` | 브러시 입력 종료 (이미지 저장 및 알파맵 초기화) |
| `cancel()` | 브러시 입력 취소 (변경사항 취소 및 원본 복구) |
| `exit()` | 브러시 모드 종료 |
| `setSize()` | 캔버스 크기 변경 시 텍스처 리사이징 |

---

## 🚩 stroke의 상세한 동작 원리

- 사용자가 터치 이동 시 매번 호출됨.
- 최적화를 위해 SCISSOR_TEST로 **오직 브러시가 영향을 주는 영역만** 렌더링.
- 알파맵 업데이트 시에는 `pathTex` ↔ `pathTexOut` 텍스처 간의 블리팅을 통해 지속적으로 알파값을 누적하여 사용.

---

## 🚩 brush / eraser의 상세한 동작 원리

- stroke로 만든 알파맵을 실제 레이어에 반영.
- 브러시 색상이나 지우개 효과는 여기서 실제 이미지 픽셀을 직접 변경.
- 각 프레임마다 호출되는 것이 아니라 stroke가 끝난 후 호출됨 (브러시 떼거나 완료 시)

---

## 🚩 clearMap()의 중요성 이해하기

- 브러시 작업이 완료되면 `clearMap()`을 호출하여 알파맵(`pathTex`)을 초기화 (모든 픽셀을 0으로 초기화).
- 알파맵을 다음 브러시 입력을 위해 비워둬야 함.

---

## 🚩 레이어 및 히스토리 구현 시 고려사항 (중요🔥)

브러시 작업을 히스토리에 추가할 때는 다음 정보를 저장해야 합니다.

- 변경 영역의 이미지 데이터 (브러시를 그린 영역만 캡쳐)
- 브러시 입력 직전의 원본 이미지 텍스처 (`sourceTextureManager.uploadCurrent()`로 관리됨)
- 필요한 경우 stroke 정보를 추가로 저장 가능 (선택 사항)

**즉, 히스토리 기능 개발자는 브러시 입력 전후로 `sourceTextureManager`의 이미지를 관리하고, 변경된 픽셀 정보를 저장 및 복원할 수 있어야 합니다.**

---

## 🚩 지금 이해해야 할 가장 중요한 포인트

- 알파맵을 기반으로 브러시 효과가 구현됨
- `strokeShader`가 핵심이며, 알파맵을 만드는 단계임
- 실제 이미지 변경은 `brushShader`, `eraserShader`에서 수행
- 히스토리는 `sourceTextureManager`의 이미지 관리가 핵심

---

## 🚩 정리된 핵심 데이터 흐름 도식화

```
[사용자 입력 (좌표)] → strokeShader → 알파맵(pathTex)
                  ↓
         brushShader or eraserShader → 실제 이미지 변경
                  ↓
          변경 완료 후 → sourceTextureManager에 저장
```

히스토리는 위 흐름에서 **"변경 완료 후 저장된 이미지"**를 활용합니다.
